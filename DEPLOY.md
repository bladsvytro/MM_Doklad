# Инструкция по развертыванию на GitHub Pages

Этот документ содержит подробные инструкции по публикации презентации "Начала Евклида" на GitHub Pages.

## 📋 Предварительные требования

1. **Аккаунт GitHub** - если нет, создайте на [github.com](https://github.com)
2. **Репозиторий** - этот проект должен быть в репозитории GitHub
3. **Доступ к интернету** - для загрузки файлов

## 🚀 Быстрый старт (автоматический деплой)

### Вариант 1: Через GitHub Actions (рекомендуется)

Проект уже настроен для автоматического деплоя. Просто выполните:

1. Загрузите все файлы в репозиторий `bladsvytro/MM_Doklad`
2. Перейдите в `Settings → Pages` вашего репозитория
3. Убедитесь, что выбрано:
   - **Source**: GitHub Actions
   - **Branch**: main
4. Система автоматически развернет сайт через несколько минут

Сайт будет доступен по адресу:  
`https://bladsvytro.github.io/MM_Doklad/`

### Вариант 2: Через ветку gh-pages

Если автоматический деплой не работает:

```bash
# Клонируйте репозиторий
git clone https://github.com/bladsvytro/MM_Doklad.git
cd MM_Doklad

# Создайте ветку gh-pages
git checkout -b gh-pages

# Запушьте ветку
git push origin gh-pages
```

Затем в настройках репозитория выберите:
- **Source**: Deploy from a branch
- **Branch**: gh-pages
- **Folder**: / (root)

## 🔧 Ручная настройка GitHub Pages

### Шаг 1: Настройка репозитория

1. Перейдите на страницу вашего репозитория на GitHub
2. Нажмите `Settings` (вкладка справа)
3. В левом меню выберите `Pages`
4. В разделе `Build and deployment`:
   - **Source**: Deploy from a branch
   - **Branch**: main
   - **Folder**: / (root)
5. Нажмите `Save`

### Шаг 2: Ожидание деплоя

GitHub Pages обычно развертывает сайт в течение 1-10 минут. Вы можете проверить статус:

1. Вернитесь в `Settings → Pages`
2. Посмотрите раздел `GitHub Pages`
3. Должна появиться зеленая галочка и ссылка на ваш сайт

### Шаг 3: Проверка сайта

Перейдите по ссылке, которая появилась в настройках Pages. Обычно это:
```
https://<username>.github.io/MM_Doklad/
```

## 🐛 Устранение неполадок

### Проблема 1: Сайт не загружается
**Симптомы:** Белая страница или ошибка 404
**Решение:**
1. Проверьте, что файл `index.html` находится в корне репозитория
2. Убедитесь, что в настройках Pages выбран правильный branch и folder
3. Подождите 5-10 минут и обновите страницу
4. Проверьте консоль браузера на наличие ошибок JavaScript

### Проблема 2: MathJax формулы не отображаются
**Симптомы:** Видны коды LaTeX вместо формул
**Решение:**
1. Проверьте подключение к интернету (MathJax загружается из CDN)
2. Убедитесь, что в консоли нет ошибок CORS
3. Проверьте, что MathJax загружен: `window.MathJax` должен существовать

### Проблема 3: Интерактивные элементы не работают
**Симптомы:** Кнопки не реагируют, Canvas не рисует
**Решение:**
1. Проверьте консоль браузера на ошибки JavaScript
2. Убедитесь, что файлы `geometry.js` и `main.js` загружены
3. Проверьте права доступа к файлам (должны быть 644)

### Проблема 4: Стили не применяются
**Симптомы:** Страница выглядит неотформатированной
**Решение:**
1. Проверьте путь к файлу `css/styles.css`
2. Убедитесь, что файл существует и загружен
3. Проверьте MIME-типы на сервере

## 🔍 Проверка перед деплоем

Перед загрузкой на GitHub проверьте локально:

```bash
# Запустите локальный сервер
python -m http.server 8000

# Или используйте любой другой сервер
# npx serve .
# php -S localhost:8000
```

Откройте `http://localhost:8000` и проверьте:
- [ ] Все слайды отображаются
- [ ] Формулы MathJax работают
- [ ] Интерактивные элементы функционируют
- [ ] Стили применяются корректно
- [ ] Навигация работает (стрелки, пробел)
- [ ] Адаптивность на разных размерах экрана

## 📊 Мониторинг деплоя

### Проверка статуса деплоя

1. **Actions вкладка:** Перейдите в `Actions` вашего репозитория
2. **Последний workflow:** Найдите workflow "Deploy to GitHub Pages"
3. **Статус:** Должен быть зеленый значок ✓

### Логи деплоя

Если деплой не удался, проверьте логи:
1. В `Actions` нажмите на неудачный workflow
2. Разверните шаг `Build` или `Deploy`
3. Ищите ошибки в логах

## 🔄 Обновление сайта

После внесения изменений в код:

```bash
# Добавьте изменения
git add .

# Зафиксируйте
git commit -m "Обновление презентации"

# Запушьте в main
git push origin main
```

GitHub Actions автоматически развернет новую версию. Обновление занимает 1-5 минут.

## 🌐 Кастомный домен (опционально)

### Настройка домена

1. Купите доменное имя у регистратора
2. В настройках DNS добавьте записи:
   ```
   A     @     185.199.108.153
   A     @     185.199.109.153
   A     @     185.199.110.153
   A     @     185.199.111.153
   ```
   ИЛИ
   ```
   CNAME www   username.github.io
   ```

3. В настройках репозитория GitHub:
   - `Settings → Pages → Custom domain`
   - Введите ваш домен
   - Нажмите `Save`

4. Дождитесь применения изменений (до 24 часов)

### Проверка домена

```bash
# Проверьте DNS записи
nslookup ваш-домен.com

# Проверьте SSL сертификат
curl -I https://ваш-домен.com
```

## 🔒 Безопасность

### Рекомендации по безопасности

1. **Не храните секреты** в коде
2. **Используйте HTTPS** (GitHub Pages предоставляет автоматически)
3. **Проверяйте зависимости** на уязвимости
4. **Ограничьте доступ** если необходимо

### CSP (Content Security Policy)

При необходимости можно добавить CSP в `index.html`:

```html
<meta http-equiv="Content-Security-Policy" 
      content="default-src 'self'; 
               script-src 'self' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net https://polyfill.io;
               style-src 'self' https://cdnjs.cloudflare.com https://fonts.googleapis.com;
               font-src 'self' https://fonts.gstatic.com;
               img-src 'self' data: https:;">
```

## 📈 Аналитика (опционально)

Для отслеживания посещений можно добавить Google Analytics:

1. Добавьте в `index.html` перед закрывающим `</head>`:
```html
<script async src="https://www.googletagmanager.com/gtag/js?id=GA_MEASUREMENT_ID"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'GA_MEASUREMENT_ID');
</script>
```

2. Замените `GA_MEASUREMENT_ID` на ваш ID из Google Analytics
